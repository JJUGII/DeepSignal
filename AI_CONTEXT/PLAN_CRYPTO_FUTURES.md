# 기획서 ② — 코인 선물(숏) 도입

작성: 2026-06-15 · 분석엔진 담당 · 성격: **사업/규제 결정 + 기술 검증**

---

## 1. 배경 / 문제

- 현재 코인은 **Upbit 현물**뿐 → 하락에서 *수익* 불가, "하락 중 반등 롱"만 가능.
- 진짜 하락장 수익(숏)은 **선물/마진/인버스** 가 필요 = 완전히 다른 인프라.
- 정직한 전제 두 가지:
  1. **주식 타이밍 숏은 98년 백테스트로 기각됨**(우상향 드리프트·베어랠리·인버스 decay). 코인은 *드리프트가 약해* 같은 논리가 그대로 적용되진 않으나, **펀딩비·청산비라는 새 비용**이 생긴다.
  2. **코인 숏 엣지는 미검증** — 검증 전엔 주식처럼 기각될 수도. 게다가 레버리지로 **손실 속도가 훨씬 빠름**.

## 2. 목표

> 검증된 엣지가 있을 때에 한해, **별도 자본·별도 엔진**으로 하락장 코인 숏 수익. 검증 전엔 한 푼도 안 넣음.

## 3. ⚠️ 선결 — 사용자 결정 영역 (기술 이전)

이건 코드로 못 푸는, **사용자가 먼저 결정·확인할 사안**:

| 항목 | 내용 |
|------|------|
| **거래소 선택** | 해외 선물 거래소(Binance/Bybit/OKX 등). Upbit 불가 |
| **규제/법무** | 한국 거주자의 해외 코인 파생 거래는 **회색지대**. KYC·접속 제한·세무 신고 의무를 **본인이 법무·세무로 확인** 필수 |
| **자본 분리** | 현물 자본과 **완전 분리된 별도 자본**(레버리지 청산 리스크 격리) |
| **레버리지 한도** | 청산 방지 위해 저배율(예 1~2x) 원칙 |

→ **이 4개가 결정/확인되기 전엔 기술 단계로 못 넘어감.**

## 4. 단계별 계획 (선결 후)

| Phase | 내용 | 산출물 | 비고 |
|-------|------|--------|------|
| **F0 데이터 인프라** | 선물 시세 + **펀딩비·미결제약정·청산데이터** 수집 파이프라인 | 데이터 수집기 | 신물 |
| **F1 숏 엣지 백테스트** | 코인 숏이 **펀딩비+수수료+슬리피지 차감 후 양(+)인지** OOS 평가. (주식처럼 기각될 수 있음) | `scripts/eval_crypto_short_edge.py` | **여기서 음이면 폐기** |
| **F2 리스크 모델** | 청산가 버퍼·레버리지 상한·펀딩비 손익·강제청산 시나리오 | 숏 리스크 엔진 | 필수 |
| **F3 페이퍼** | 거래소 testnet/페이퍼로 숏 셋업 200건 검증 | 검증 리포트 | |
| **F4 카나리 라이브** | 분리 자본 소액·저배율 실거래 | — | 검증 통과시만 |

## 5. 안전장치

1. **별도 자본·별도 계정**(현물과 격리)
2. **저배율 상한**(1~2x) + 청산가 버퍼 강제
3. F1 백테스트 게이트 — 펀딩·비용 후 엣지 없으면 폐기
4. 페이퍼 검증 → 카나리 → 확대
5. 일일 손실 한도·킬스위치(기존 TRADING_HALT 확장)

## 6. 성공 기준

- **F1**: 코인 숏이 펀딩비·수수료·슬리피지 차감 후 OOS에서 PF≥1.2 & net+ (미달 시 **도입 자체 폐기**)
- **F3**: 페이퍼 200건 net+
- **F4**: 카나리 net+ 지속, 청산 0건

## 7. 리스크 (현물보다 큼)

| 리스크 | 심각도 | 대응 |
|--------|--------|------|
| 레버리지 청산(원금 손실) | 🔴 | 저배율·청산버퍼·분리자본 |
| 펀딩비 누수(숏 캐리) | 🟡 | F1에서 비용 반영 검증 |
| 규제·세무 | 🔴 | 사용자 사전 확인(선결) |
| 숏 엣지 미검증(기각 가능) | 🟡 | F1 백테스트로 선제 거름 |
| 24시간 변동·갭 | 🟡 | 손실한도·킬스위치 |

## 8. 정직한 권고

> **서두를 일이 아닙니다.** 주식 숏이 기각된 것처럼 코인 숏도 검증 전엔 미지수이고, 레버리지 탓에 **틀리면 더 빨리·크게 잃습니다.** 권하는 순서:
> 1. (사용자) 거래소·규제·자본분리 결정
> 2. F1 **백테스트로 "코인 숏이 펀딩·비용 후 정말 돈이 되는가"부터** 확인 — 이게 음수면 도입 자체를 접는다.
> 3. 양수일 때만 페이퍼 → 분리자본 카나리.
>
> **현물 손실 방어(하락장 안 잃기)는 이미 DM6·하락장엔진으로 대응 중**이라, 선물은 "추가 수익원" 옵션이지 급한 불이 아닙니다.

## 9. 한 줄 요약

> **선물은 코드 문제가 아니라 사업·규제·검증 문제다.** 거래소·법규·자본분리(사용자 결정) → 펀딩비 반영 백테스트(F1)로 엣지부터 입증 → 통과 시에만 분리자본 소액. **엣지가 먼저, 레버리지는 한참 나중.**
